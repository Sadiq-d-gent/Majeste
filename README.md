# MAJESTÉ
**A Mark of Distinction.**

An exclusive luxury celebration experience, built around an effortless journey from event creation to secure guest admission.

## Status
**Frontend planning / design foundation.** No production application, backend verification, or live admissions are claimed.

## Product boundaries
- Focused MVP: public brand site, curated Collections, event draft creation, guest management, invitation preview and sharing, RSVP, Pass presentation, assigned Gate scanning, and essential Studio operations.
- Advanced security and privacy policies remain binding; frontend mock interactions must never claim actual authentication, QR redemption, email delivery, or data persistence.
- Post-MVP: Professionals, Venues, photographer portfolios / consented galleries / verified reviews (MJT-FUT-001), native apps, advanced integrations.
- Design: quiet luxury, restrained black/gold, typography-led hierarchy, selective glass, accessibility, responsive mobile-first layout, no ornamental clutter.
- Pricing: intentionally premium, backed by genuine quality and service; do not invent prices or testimonials.

## Source of truth
The 45 approved decisions and luxury positioning charter supersede conflicting draft policy. The previous v2.1 package is a controlled *interim* reconciliation, not an approved implementation baseline. The implementation must still define and test transactional Gate semantics, permissions, retention, and failure behavior.

See [Frontend execution plan](docs/FRONTEND_PLAN.md).

## Development approach
Work in reviewable phases; do not call the entire frontend complete until all specified routes and user journeys are implemented, visually reviewed, accessibility-checked, and tested. Backend integration is a separate phase with production security gates.

## Repository note
This repository is **public**. Do not commit credentials, private guest data, customer records, or unpublished confidential assets.
